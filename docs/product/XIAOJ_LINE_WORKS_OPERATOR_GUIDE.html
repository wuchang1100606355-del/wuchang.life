XiaoJ LINE WORKS 產品化操作指南

目標：先上候選通知與本地權威 gate，不讓 AI 或 UI 直接發送 LINE WORKS 訊息。

目前你已經有什麼

API

/wuchang/xiaoj/api/lineworks-notify 已設計為登入使用者可呼叫的候選通知 API。

HOLD

正式發送 gate 是 lineworks_send，未有 verified release refs 前不發送。

Preflight

/wuchang/xiaoj/api/lineworks-send-preflight 可檢查是否具備正式發送條件，但仍不連外。

不要做

  • 不要把 LINE WORKS access token、refresh token、client secret、private key 貼到聊天、文件或 repo。
  • 不要把會員電話、完整姓名、地址、LINE/WORKS raw profile 當通知 payload。
  • 不要直接呼叫 LINE WORKS API 測試正式發送，先完成 verified release refs。
  • 不要讓雲端 AI 決定誰可接收通知；AI 只能產生候選文字。
  • 不要讓總場持有 Google Workspace、LINE WORKS、Odoo、router 或付款系統的明文高權限憑證。

總場數位代理邊界

總場可以作為你的數位代理做候選判斷、分場查詢、本地准駁、release preflight 與 evidence seal；它不應成為無限制超管，也不應超越人類 owner/admin root-of-trust。

可代理建立候選、查分場、產生 authority packet、執行 local verifier、整理 HOLD / READY / DEAD_LETTER 狀態。
不可代理保存明文密碼、保存 token、繞過 verified release refs、直接變更 Google Workspace 或外部平台高風險設定。
正式動作必須由人類 owner/admin 或已驗證 release packet 啟用；總場只能提供預檢與證據封存。

你在 LINE WORKS 後台要做的事

  1. 進入 LINE WORKS Developer Console 或管理後台。
  2. 建立或確認 XiaoJ 專用 App，不要用個人測試 App 混用正式店務。
  3. 建立或確認 Bot，記下 Bot ID。只記 Bot ID ref，不貼 token。
  4. 啟用 scope：bot 與 bot.message。
  5. 決定第一版授權方式：Service Account JWT 或 OAuth。若不確定，先選 Service Account JWT 做後端 connector。
  6. 把 Bot 加到測試網域與測試使用者可收到訊息的位置。
  7. 準備一個測試 target user ref。只提供 ref 或 hash，不提供會員明文。
  8. 先執行 xiaoj_lineworks_operator_handoff_pack.py 產生操作交接包，確認缺哪些 refs。
  9. 使用 lineworks-release-refs-draft API 或 xiaoj_lineworks_release_refs_builder.py 產生 refs 草稿。

你在 Odoo 後台要做的事

  1. 等我完成 module upgrade 前，不要急著正式送出；目前只是程式已具備模型與畫面。
  2. 升級後進入 WuChang Cafe / LINE WORKS Candidates。
  3. 建立候選通知，填 message_preview、target_ref_hash、channel。
  4. 按 Build Candidate 產生候選封包與 evidence hash。
  5. 填入 verified release refs JSON 與 connector refs。
  6. 按 Build Release Refs Draft 正規化 refs，產生 draft hash 與 warnings。
  7. 按 Run Preflight。若狀態是 preflight_ready，代表正式 connector 條件齊備，但仍未送出。
  8. 按 Build Execution Envelope 產生 redacted execution envelope，不要交付 token 或會員明文。
  9. 填入 runtime_operator_ref 後，按 Build Runtime Activation 產生 activation packet hash。
  10. 填入 resolver binding metadata 後，按 Build Resolver Contract；只填 binding ref 與 value hash，不填 bot ID、user ID 或 token 原文。
  11. 按 Runtime Dry-Run 檢查 P2 connector 是否具備人審啟用條件。
  12. 按 Build Handoff Pack 產生操作交接包，集中查看 release refs、execution envelope、activation、dry-run 與下一步。
  13. 若資料錯誤或可疑，按 Dead Letter 留存審核。

P2 Connector Refs

正式 connector 只接受 ref，不接受 token 或 private key 原文。模板檔同樣在 packets/product_av_ordering_ai/lineworks_release_refs_template.json。

{
  "connector_refs": {
    "lineworks_bot_ref": "BOT_REF_CAFE_XIAOJ_PILOT",
    "lineworks_target_user_ref": "TARGET_REF_HASHED_PILOT",
    "lineworks_access_token_runtime_ref": "RUNTIME_TOKEN_PROVIDER_REF_ONLY"
  }
}

若任何 ref 長得像 access token、Bearer token、client secret 或 private key，preflight 會 HOLD。

P2 Runtime Connector 邊界

目前已有可接上的 runtime connector 函式，但預設只做 dry-run，不會發送 LINE WORKS。

函式wuchang_cafe_ai_gateway.services.lineworks_connector.execute_lineworks_send_envelope
API/wuchang/xiaoj/api/lineworks-execution-envelope、/wuchang/xiaoj/api/lineworks-runtime-activation-draft、/wuchang/xiaoj/api/lineworks-runtime-resolver-contract、/wuchang/xiaoj/api/lineworks-runtime-dry-run 與 /wuchang/xiaoj/api/lineworks-operator-handoff
預設enable_external_call=false，所以 external_api_call=false、formal_lineworks_send=false。
正式送出前必須有 human activation packet、64-hex activation hash、安全 operator ref、runtime resolver。
不可回顯bot ID、target user ID、access token、LINE WORKS response body。
安全限制Dry-run API 不接受也不採用前端傳來的 enable_external_call。
