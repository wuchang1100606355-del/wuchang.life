# D8 Pricing Model Draft

## Pricing Principle

D8 should be sold as a local-first governance service package, not as a generic chatbot subscription.

## Package Draft

| Package | Target | Includes | Draft price hypothesis |
|---|---|---|---|
| Pilot Setup | First cafe/community proof field | local install, safety boundary map, one demo package, one sealed pilot report | one-time setup fee |
| Local Governance Maintenance | Ongoing SMB use | backup checks, guard review, report/seal hygiene, redteam/alert review | monthly retainer |
| Odoo/POS Safe Bridge Add-On | Odoo/POS operators | read-only manifest, eventbook/menu evidence, no payment/order writes | add-on fee |
| Custom Governance Rules | Cafe/association/committee workflows | local rules, task templates, forbidden paths, preflight capsules | project fee |
| On-Prem / Local-First Package | privacy-sensitive teams | local-only deployment, handoff runbook, reviewer training | premium setup + maintenance |

## Pricing Validation Needed

- Interview cafe owner/operator.
- Interview small development teams using AI coding agents.
- Compare cost of one governance incident vs monthly D8 maintenance.
- Validate willingness to pay for sealed reports and read-only POS/Odoo safety.

## Boundary

Do not price as a production AI automation platform until formal testing and release gates pass.
