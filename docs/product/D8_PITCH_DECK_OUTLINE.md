# D8 Pitch Deck Outline

## Slide 1: Title

D8 Total Field Agent Governance Console

Local-first AI agent governance for Odoo/POS and SMB operations.

## Slide 2: The Problem

AI agents can read files, run commands, inspect systems, and produce operational reports. Small teams need a practical local gate before agents touch code, Odoo/POS evidence, or business workflows.

## Slide 3: The First Wedge

Odoo + POS + cafe/community local operations.

Proof field:

聊國咖啡館重新總店.

## Slide 4: Product One-Liner

D8 checks total field state, redteam history, possible alerts, and guard evaluations before agent action, then seals the result and writes failures back as future guardrails.

## Slide 5: Why This Is Not Another Coding Agent

Codex, Claude Code, Cursor, Devin, Aider, and OpenHands help agents do work.

D8 helps teams decide whether agent work should proceed.

## Slide 6: Product Loop

State -> Coordinate -> Hash -> Packet -> Generative Transfer -> Verify -> Reconstruct -> Evidence -> Action

Operational MVP loop:

Preflight -> Alerts -> Redteam -> Guard Eval -> PASS/HOLD/BLOCK -> Seal -> Writeback

## Slide 9: Differentiation

- Failure events become future warnings.
- Redteam records are non-executable.
- Redteam retrieval is isolated from executable task context.
- Local-first operation avoids unnecessary cloud exposure.
- Seals create handoff and audit continuity.

## Slide 10: MVP Boundary

- Read-only Odoo/POS bridge.
- No payment.
- No POS order.
- No member plaintext.
- No production deploy.
- No external API or embedding in launch package.
