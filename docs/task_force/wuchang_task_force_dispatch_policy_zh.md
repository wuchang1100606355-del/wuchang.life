# 五常社區專勤隊派單規則

日期：2026-05-12  
狀態：設計規格生效；尚未接入 production 派單  
場景：外送、社區服務、健康訪視、照服員協同  
Odoo 承載：`wuchang_core` 模組內之「聊國咖啡館仁義店志工業務」與「社區專勤隊派單留痕」  
分公司範圍：聊國咖啡館仁義店 / 社區產業基金本體店  
後台角色：志工隊督導 1 人由仁義店店長兼任；志工隊隊長 1 人目前佔缺  
基金子帳：仁義店五常社區數位發展基金子帳戶 / 志工隊收支帳  

## 核心規則

社區專勤隊外送任務採「排班設備群呼 + 掛牌待命 + 第一位按停得單 + 照服員當勤留痕」。

流程：

```text
訂單/服務任務產生
  -> 檢查當日排班
  -> 找出可用設備與掛牌待命者
  -> 對設備群呼
  -> 第一位按停/接單者取得任務
  -> 其他設備停止提示
  -> 照服員記為當勤責任人員
  -> 寫入 audit / rollback / no-delete ledger
```

## 名詞

| 名詞 | 定義 |
| --- | --- |
| 排班 | 當日允許接單的時段、人員、角色與服務區域 |
| 設備群呼 | 對符合條件的設備同時發出任務提示 |
| 掛牌者 | 已登入、已待命、願意接單、符合權限與場域的人員 |
| 第一位按停者 | 第一個在有效時間內按下接單/停止鈴聲的人 |
| 得單 | 任務臨時指派成功，不等於可繞過安全檢核 |
| 當勤照服員 | 當班責任人員，負責服務安全、照護邊界與突發回報 |

## 派單條件

任務只可派給同時符合以下條件的人員/設備：

- 位於當日排班中。
- 狀態為掛牌待命。
- 設備在線且可通知。
- 未超過個人任務上限。
- 符合服務類型資格。
- 未處於休息、離線、暫停、風險隔離。
- 任務地點屬於可服務區域或人工核准區域。

## 第一位按停者得單

第一位按停者取得任務，但系統仍需檢查：

- 是否仍在有效搶單時間窗。
- 是否同時有多設備近乎同時按停。
- 是否具備服務資格。
- 是否需要照服員陪同。
- 是否觸發 L2/L3 風險。

同毫秒或競態狀況時，以伺服器接收時間與 audit sequence 為準；若無法判定，任務進入人工重新派單。

## 照服員當勤規則

照服員是當勤責任人員，不一定是實際外送者。照服員需要：

- 確認任務安全。
- 監看高齡、弱勢、兒童、夜間或健康訪視任務。
- 處理異常回報。
- 對高風險任務進行人工確認。
- 保留當勤 audit。

照服員不得因當勤身分取得會員明文或醫療明細，除非任務已通過人類決策與最小必要權限。

## 志工管理後台角色

Odoo `wuchang_core` 設立 `五常志工管理後台` 群組，供志工管理使用。

| 角色 | 人數 | 設定 | 權限定位 |
| --- | --- | --- | --- |
| 志工隊督導 | 1 | 由聊國咖啡館仁義店店長兼任 | 志工業務後台管理、派單留痕審視、會議召集、風險確認 |
| 志工隊隊長 | 1 | 目前佔缺 | 協助督導管理志工隊、接單秩序、排班協調 |

志工管理後台不得取得付款、退款、私下收款、會員明文、Google Workspace 超管或 Odoo 系統管理員權限。

## 志工管理會議與 Google 會議功能

Odoo 建立模型 `wuchang.volunteer.management.meeting`，用於登錄志工管理會議。

欄位包含：

- Google Meet 連結。
- Google Calendar Event Ref。
- 會議召集人。
- 志工隊督導。
- 志工隊隊長。
- 議程不含會員明文。

目前只建立 Odoo 後台紀錄欄位，不直接呼叫 Google API。正式建立 Google Meet 需另走 Google Calendar 授權窗、最小 scope、audit 與人類確認。

## 仁義店基金子帳戶 / 志工隊收支帳

Odoo 建立模型 `wuchang.renyi.volunteer.account`，作為：

```text
仁義店五常社區數位發展基金子帳戶 - 志工隊收支帳
```

用途：

- 記錄志工隊相關收入、支出、補貼與公益服務支援之審核摘要。
- 保持在「權限可見 / 可稽核」或「公開科目與摘要」層級。
- 不公開明細、不公開憑證、不公開會員明文、不公開商業機密。
- 不直接執行付款，不直接改正式會計帳。

Odoo 建立模型 `wuchang.renyi.volunteer.account.line` 作為收支審核明細。錯誤紀錄不得刪除，只能送審、沖銷留存或作廢留存。

## 風險分級

| 場景 | 等級 | 動作 |
| --- | --- | --- |
| 普通餐飲外送 | L1 | allow_with_audit |
| 夜間外送、雨天、偏遠路線 | L2 | warn + 照服員確認 |
| 涉及兒童、長者、健康訪視 | L2/L3 | require_human_confirmation |
| 付款、退款、私下收款 | L3 | block |
| 會員明文、住址外流、追蹤路徑上雲 | L3 | block |

## 不可刪除

派單、按停、得單、改派、作廢、錯派、取消都不得物理刪除。錯誤派單只能：

- 記名取消。
- 改派留痕。
- 錯單更正。
- 沖銷服務點數。
- 新增查核註記。

## 最小資料原則

群呼設備只應收到完成任務必要資訊：

- 任務類型。
- 大略服務區域或取送點代碼。
- 時間窗。
- 是否需照服員陪同。
- 風險等級。

不得在群呼中廣播完整會員姓名、完整地址、電話、健康狀況或付款資訊。

## Odoo 內分公司志工業務映射

此政策已映射至 Odoo `wuchang_core` 模組檔案層，尚未執行 live DB 安裝或 production 派單。

### 志工業務模型

模型：`wuchang.renyi.volunteer.business`

用途：

- 將「聊國咖啡館仁義店」作為社區產業基金本體店之志工業務承載點。
- 記錄餐飲外送、社區服務、健康訪視、照服員協同等業務類型。
- 固定預設 `branch_scope = renyi_store`。
- 固定預設 `supervisor_role = renyi_store_manager`。
- 固定預設 `captain_role = vacant`，表示志工隊隊長目前佔缺。
- 記錄群呼、第一位按停者得單、照服員當勤留痕等政策開關。
- 預設 `live_dispatch_enabled = false`，代表目前只完成 Odoo 模型骨架與政策承載，不代表 production 派單啟用。

### 派單留痕模型

模型：`wuchang.task.force.dispatch`

用途：

- 承接單次任務派單紀錄。
- 記錄排班時段、服務區域代碼、設備群呼開始時間、第一位按停者、當勤照服員、風險等級與狀態。
- L2/L3 或需人工確認任務進入 `human_review`。
- 涉及會員明文或付款/退款時直接封鎖，不得進入群呼。

### Odoo 選單

新增於 `Wuchang OS`：

- `聊國仁義店志工業務`
- `社區專勤隊派單`
- `仁義店志工隊收支帳`
- `志工隊收支審核明細`
- `志工管理會議`

## 開發期限制

目前為開發期模型寫入：

- 不安裝 Odoo module。
- 不重啟 Odoo container。
- 不寫 live Odoo DB。
- 不建立正式會員資料。
- 不處理付款、退款、私下收款或正式會計。

正式啟用前需：

- Odoo 模組升級審核。
- 會計分窗確認。
- 照服員/志工角色權限確認。
- Gateway / Five Metric Gate / Audit log 接線。
- 人類決策確認。
