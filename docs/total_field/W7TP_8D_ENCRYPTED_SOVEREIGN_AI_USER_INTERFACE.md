## Authority Boundary

The interface may:

- listen to user intent,
- classify service context,
- draft a candidate response,
- guide a controlled browser action,
- package visible user-side state into ref-only 8D packets,
- request precise, low, non-inferable redacted cloud candidate help,
- attach D7 proof, nonce / timestamp, hash refs, evidence refs, and no-plaintext flags,
- send candidate packets to the total field.

The interface must not:

- become the total field,
- make final decisions,
- write production Odoo records,
- capture payment,
- retain member plaintext,
- store raw browser pages,
- read secrets,
- use cloud output as authority,
- send enough cloud context to reconstruct the user or exact browser state,
- bypass social worker, caregiver, property, association, or member confirmation gates.

## Cloud Minimality And Non-Inference

Cloud dependency is allowed only if all three conditions hold:

```text
PRECISE: only the bounded missing capability is sent.
LOW: token volume, call frequency, latency, cost, and exposure are minimized.
NON_INFERABLE: cloud cannot infer user identity, raw browser state, health/care context, household location, or stable cross-session behavior.
```

The cloud request may include task refs, redacted summaries, output schema refs, coarse preference buckets, one-shot nonce, short TTL, and candidate-only instructions.

It must not include member plaintext, raw browser pages, raw clickstream, exact address, raw care details, payment data, credentials, cookies, OAuth tokens, API keys, stable cloud user identifiers, or proprietary total-field rule tables.
