# 8D 因果主張檢查（候選）
來源：江政隆於 2026-09-27 本對話要求；保留其技術定義與來源主張。
這是既有 tools/d8_guard_eval.py 的純函式與命令列擴充，不是第二總場或完整八維場。
入口：evaluate_causal_claims(payload)；CLI：python3 -B tools/d8_guard_eval.py --causal-claims-stdin
輸入以標準輸入提供 JSON，完整例子見 tests/test_d8_causal_claims.py 的 packet()。
輸出碼 0 僅為 CANDIDATE_CONSISTENT（候選內部一致）；30 為 HOLD_CAUSAL_CLAIMS（主張待釐清）。

## 固化的因果邊界
八维場不能線性化；重新查詢不能冒稱重構；登錄或排隊不能冒稱已執行或驗收；
歷史成功或失配綁定不能冒稱當前就緒；規則主體傳送不能被零原始位元組計數抹去；
必要依賴失效必須停止依賴動作，独立工作可保留；堆疊不能自行增加權限；
名稱與時間相近不能證明因果；等價效果需要相同任務與驗收的對照觀測；
可能改變狀態的觀測器不能冒稱唯讀。

## 接點與限制
此入口只讀取呼叫者提供的結構化主張，不執行工具、不連資料庫、不驗證來源真实性。
每項主張綁定節點、物件、狀態版本、含時區時間及證據引用；座標一致不等於證據真實或新鮮。
schema 中的欄位是檢查介面，不是八維本體；沒有主張、不認識的主張、缺欄位或錯型別皆暫停。
自然語言轉換仍可能誤譯或漏報，故不能宣稱此工具保證 AI 理解正確。
尚未接入正式模型輸出、任務派送或服務；不改既有文字規則、V2.1 指標或正式裁決。
歷史錯誤只是回歸案例，不能自動推斷目前仍有同一故障。
現有測試涵蓋九類主張、錯節點／版本／時間、重複、空輸入、型別欺騙與無資料庫 CLI 路徑。
