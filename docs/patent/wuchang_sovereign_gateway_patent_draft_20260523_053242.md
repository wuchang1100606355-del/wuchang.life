### 三、技術領域

本發明涉及分散式人工智慧、邊緣運算、主權運算、零信任存取控制、任務路由、節點權限配工、死信箱防呆、可驗證執行證據鏈，以及可選的度規張量拓樸路由方法。

本發明不主張單純抽象數學公式本身，而是主張一種在具體電腦系統、服務埠、節點狀態檔、systemd 啟動單元、API 匝道器、死信箱與 ledger 中實作的技術架構。

---

### 四、先前問題

傳統 AI 系統常存在以下問題：

1. 大模型、UI、資料庫、工具節點與管理權限混雜，導致權限邊界不清。
2. AI 代理人在使用工具時，容易產生越權執行、誤刪資料、錯誤改 DNS、暴露金鑰、錯誤財務或法律承諾等風險。
3. 多節點系統缺乏統一節點強弱評分、任務配工、狀態回報與失敗證據鏈。
4. 離線狀態下，系統若仍能執行高風險任務，會造成主權失控。
5. 單純的聊天模型或自動化腳本不能有效區分「可執行任務」、「需等待人類核准任務」與「必須拒收任務」。

---

### 五、發明概要

本發明提供一種分散式主權 AI 系統，其包含：

1. `01_admin` 主權規則層，用於保存根權限政策、離線/在線授權規則與核准佇列。
2. `Gateway` 匝道器，用於接收任務、讀取拓樸、驗證權限、選擇節點、拒收越權任務。
3. `02_edge_nodes` 邊緣節點層，用於定義 taiji01、openwebui、odoo、sensor 等節點身分、角色、能力與上限權限。
4. `03_UI` 互動層，用於 Open WebUI 與 OpenWebUI Bridge 之人機互動與模型 API 入口。
5. `runtime/state` 狀態層，用於記錄節點當前在線狀態、PID、啟動檔雜湊與管理單元。
6. `runtime/dead_letter` 死信箱層，用於保存越權、不確定、衝突、高風險與無法路由之任務。
7. `runtime/ledger` 證據鏈層，用於追加式記錄啟動、路由、健康檢查、拒收、節點心跳與系統基準點。
8. 可選的度規張量拓樸路由器，用於根據節點強弱、可信度、能耗、權限等狀態，計算任務分派優先序。

### 六、系統實施例

在一實施例中，系統包含以下本機服務：

- Gateway：127.0.0.1:8081
- Open WebUI：127.0.0.1:8080
- OpenWebUI Bridge：127.0.0.1:8098
- Ollama：127.0.0.1:11434
- Claw 工具節點：127.0.0.1:9004
- SSH Tunnel：127.0.0.1:2222

系統透過 user systemd 啟動以下服務：

- `taiji-gateway.service`
- `taiji-admin-node.service`
- `taiji-edge@taiji01.service`
- `taiji-edge@openwebui.service`
- `taiji-edge@odoo.service`
- `taiji-edge@sensor.service`
- `taiji-03-ui.service`
- `taiji-native-claw.service`
- `taiji-healthcheck.timer`

每個 edge node 具有對應的 `node_boot.yaml`，其中描述：

- 節點 ID
- 節點角色
- 信任等級
- 算力分數
- 能耗分數
- 最大權限等級
- 允許任務
- 禁止任務

### 七、關鍵技術效果

本發明的技術效果至少包含：

1. 將 AI 任務入口集中至 Gateway，降低節點直接越權執行風險。
2. 透過 `dead_letter` 使高風險、不確定、越權任務不被自動執行。
3. 透過 `ledger` 建立可驗證、可追溯的系統行為證據鏈。
4. 透過 `node_boot.yaml` 與 systemd template，使節點新增、移除與重啟具一致性。
5. 透過在線/離線權限模式，使人類不在線時系統僅能執行低風險維運、健康檢查與狀態回報。
6. 透過節點能力分數，讓系統可根據強弱、可信度與能耗進行任務配工。
7. 透過本地模型與本地 Gateway，減少不必要的外部雲端推論與資料外洩。

### 八、可選度規張量拓樸路由實施例

在一實施例中，Gateway 可讀取節點狀態，並形成節點拓樸圖。節點可具有下列參數：

- compute_score
- trust_level
- energy_score
- authority_level
- online_status
- task_role
- dead_letter_rate
- response_latency

Gateway 根據上述參數形成任務分配分數。該分數可被視為節點拓樸中的局部度規，用以表示任務與節點之間的適配距離。

此處的度規張量不是抽象數學本身，而是被用於具體控制任務路由、節點選擇、權限限制與錯誤拒收。

### 九、可選鑑識常數實施例

在一附屬實施例中，系統可使用特定常數，例如 `0xF124771717`，作為：

1. 任務簽章或路由決策之水印種子。
2. 節點狀態摘要之驗證常數。
3. 特徵壓縮或量化流程中的實施例偏移值。
4. 侵權比對或內部鑑識工具中的識別特徵。

該常數不應作為唯一主權利項核心，而應放在附屬項、實施例、鑑識流程或營業秘密中。若未來能以實驗證明該常數對延遲、能耗、記憶體存取或推論穩定性有特定技術效果，則可再提高其權利項層級。

### 十、範例權利要求草案

#### 請求項 1：系統獨立項

一種分散式主權人工智慧任務處理系統，包含：

一主權管理層，用於保存人類操作者之權限政策、離線授權規則與核准佇列；

一匝道器服務，用於接收人工智慧任務、讀取節點拓樸、檢查任務權限、選擇目標節點，並於任務不符合權限政策時將該任務寫入死信箱；

複數個邊緣節點，每一邊緣節點具有一節點開機設定檔，該節點開機設定檔定義節點角色、允許任務、禁止任務、信任等級與最大權限等級；

一狀態記錄層，用於記錄各邊緣節點之在線狀態與啟動檔雜湊；以及

一證據鏈層，用於以追加方式記錄啟動事件、路由決策、拒收事件與健康檢查結果；

其中，該匝道器服務被配置為在高風險任務、越權任務、不確定任務或節點不存在時，不自動執行該任務，而將該任務寫入該死信箱。

#### 請求項 2：權限模式附屬項

如請求項 1 所述之系統，其中該主權管理層包含在線模式與離線模式；於離線模式中，系統僅允許健康檢查、服務重啟、狀態回報與低風險本地推論，並禁止花費金錢、簽署契約、刪除核心資料、變更 DNS、揭露金鑰或對外發布法律承諾。

#### 請求項 3：節點配工附屬項

如請求項 1 所述之系統，其中該匝道器服務根據節點算力分數、信任等級、能耗分數、在線狀態、任務角色與最大權限等級，計算任務與節點間的適配分數，並據此選擇目標節點。

#### 請求項 4：死信箱附屬項

如請求項 1 所述之系統，其中該死信箱為追加式記錄檔，並禁止自動重放其中任務；該死信箱中的任務須經人類操作者審核後，方得轉入核准佇列或重新路由。

#### 請求項 5：證據鏈附屬項

如請求項 1 所述之系統，其中該證據鏈層記錄至少一者：服務啟動時間、節點心跳、節點啟動檔雜湊、路由決策、拒收原因、健康檢查結果、VPN 節點狀態與系統基準報告雜湊。

#### 請求項 6：度規拓樸附屬項

如請求項 3 所述之系統，其中該適配分數構成一拓樸度規，用以表示任務類型與節點狀態之間的距離，且該匝道器服務根據該拓樸度規執行任務路由。

#### 請求項 7：鑑識常數附屬項

如請求項 1 所述之系統，其中系統使用特定常數作為路由決策、任務簽章、節點狀態摘要或特徵壓縮流程中的鑑識識別參數，以在不揭露私鑰或完整模型權重的情況下驗證任務來源或系統實作一致性。

### 十一、目前不宜主張事項

以下內容不宜放入主權利項：

1. 全球不可繞過。
2. 絕對防剽竊。
3. 競爭對手移除特定常數即必然崩潰。
4. 尚未實測的 62 倍 DMA 降低或 8.42 GOPS/W。
5. 未有硬體仿真或對照組的 4-bit CIM 效果。
6. 未有公式與程式證明的 Christoffel / geodesic 必然性。

上述事項可保留為研究方向、附屬實施例或營業秘密，不作為目前 v0.1 主張核心。
