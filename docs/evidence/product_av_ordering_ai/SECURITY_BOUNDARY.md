# Security Boundary

STATE=SECURITY_BOUNDARY_CONVERGED

## Hard Flags

- `FORMAL_DB_WRITE=FALSE`
- `FORMAL_POS_WRITE=FALSE`
- `PAYMENT_CAPTURE=FALSE`
- `SERVICE_RESTART=FALSE`
- `DEPLOY=FALSE`
- `PRODUCTION_RELEASE=FALSE`
- `SECRET_READ=FALSE`
- `MEMBER_PLAINTEXT_READ=FALSE`

## Cloud Boundary

- Cloud/70B can produce candidates only.
- Cloud cannot receive member plaintext, payment secrets, OAuth tokens, Odoo credentials, or POS write authority.
- Cloud anchor receives display-safe refs and text only after local masking.

## Odoo Boundary

- Odoo core is not modified.
- Existing `wuchang_*` modules are the integration surface.
- Module upgrade/DB update requires operator confirmation.
- Formal POS and payment capture require separate gate and review.

## Data Boundary

- QR payloads stay short and ref-based.
- Member registration uses provisional records and hashed provider refs.
- Product photos generated by AI are candidates until human review.

## Open Source Boundary

- No unknown package install.
- Candidate libraries require license, maintenance, browser compatibility, Odoo packaging, and security review before use.
