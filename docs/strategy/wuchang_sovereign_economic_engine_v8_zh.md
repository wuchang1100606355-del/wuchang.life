# 五常主權系統 V8.0：社區造血引擎與主權經濟架構

日期：2026-05-12  
狀態：策略來源稿已治理化；未進入正式金流、會計或 Odoo production  
定位：Community Sovereign Economic Engine / 社區造血引擎  

## 核心理念

`0 EPS -> ESG` 是本系統的公益引擎。

這裡的 `0 EPS` 不是沒有商業能力，而是指社區產業與技術服務所形成的可分配盈餘，不以私人股東利潤最大化為預設目的，而是經會計分窗、章程目的、公益治理與人類決策後，轉作 ESG 影響力資本、社區服務、算力基礎設施、專勤隊支持與社區數位發展基金。

治理化表述：

- 公益不是乞求，而是可被設計、量測、查核與長期維持的能力。
- 商業智慧可以服務公益，但不得把公益資產轉為私人資本利得。
- 所有資金流、幸福幣、票券、授權金與分潤，都必須保留會計查核、錯帳更正與不可物理刪除紀錄。

## 公益商業灘頭堡原則

本系統的產品落地目的，不是做傳統商業平台的低價替代品，而是建立一個可普及、可複製、可審計的公益商業灘頭堡。

治理化表述：

- 最高級產品力是普及公益商業的必要條件；若產品不好用，公益無法贏過傳統商業。
- 平台剩餘利益、資料治理權、社區服務入口與公益造血能力，不得被中心化平台或私人資本抽乾。
- 個人、社工、照服員、店務、志工、維運者、開發者與專業服務者可以取得生活必須、薪資、津貼、合理補償與已授權智慧貢獻對價。
- 扣除生活必須、合理補償、營運成本、風險準備與會計核准支出後，剩餘利益應回到社區公益基金池、工作共同體與社區造血循環。
- 社區幣、幸福幣、票券與外送服務不是金融投機工具，而是社區需求、照護勞動、在地商業與公共價值的治理媒介。
- 去中心化不是無政府狀態，而是讓社區、社工、照服員、長輩、商家與協會擁有足夠談判力，能與中心化巨頭進行平等合作或議價。

產品判準：

```text
公益商業若要勝過傳統商業，必須同時做到：
好用、可查核、能補償工作者、能保護長輩、能留住在地利潤、能形成集體談判力。
```

### 專利先行與第一桶金路線

本系統的商業化順序已由總場修正為：

```text
先專利占位
再有限揭露銷售
先取得第一桶金
再反哺可串接社區的完整系統
```

治理化表述：

- 不應先公開完整總場核心後再尋找資金。
- `ΩGI = ⋂ᵢ₌₁⁸ Ωᵢ`、八場合一、8D intent packet、治理函數、證據回滾與無 GPU 低延遲治理驗證路徑，應先作為專利與營業秘密候選核心進入專業審查。
- 銷售階段優先販售可理解、可交付、可合約控管的外層成果，例如社區小J導入包、社工治理中樞規劃、志工隊 / 照服員派工系統、物業商業外送治理模組、Odoo 社區雲導入與 8維碼治理顧問。
- 第一桶金是打造系統與串接社區的燃料，不是脫離社區公益目的的私人抽取。
- 專利、授權、顧問、導入、維護與學術合作收入，仍須進入法務、會計、協會治理與利益衝突揭露窗口。
- AI 不得建議在未經專利與合約審查前，完整公開核心演算法、映射表、封包驗證器內部邏輯或會員資料。

總場策略句：

```text
專利先鎖核心，銷售先賣成果；
第一桶金反哺總場，總場再串接社區。
```

## 200 元外送單示例

此範例僅作設計推演，不是正式費率或合約承諾。

```text
消費者訂單：200 元
商家共利提撥：40 元
消費者社區參與溢價/支持：20 元
公益池匯流：60 元
```

治理化拆解：

- 30 元進入準備金池，可對應幸福幣或票券額度。
- 30 元留於協會治理資本池，用於社區服務、算力、專勤隊、公益防護網。
- 商家可在 POS 上產生折扣券或票券，但票券不得被設計成金融商品。
- 消費者得到在地折抵與公益參與感。
- 所有分流都必須有 Odoo 分錄、會計查核、不可刪除、可沖銷。

禁止表述：

- 不得宣稱保證獲利。
- 不得宣稱代幣可投資升值。
- 不得把公益池稱為私人可支配資金。
- 不得由 AI 自動執行付款、分潤、退款、投資。

## 技術授權與學術路徑

### 邊緣算力主權化

將 AI 推論需求優先導向本地或社區邊緣節點，使雲端成本轉為可被治理的硬體、維運與算力資產。正式技術文件應使用：

- edge-first AI runtime
- distributed compute governance
- local-truth-cloud-metric architecture
- privacy-preserving metric packet routing

避免在正式文件中使用過度物理化或不可驗證措辭。

### 5D 度規隱私封裝

在本地先進行 PII 排除與語意隔離，將任務轉成五維度規封包，再送至允許的模型或治理節點。雲端僅可見：

- metric。
- hash。
- event id。
- anonymized state。
- audit ref。

雲端不得取得會員明文、Odoo 明文、Google 私人資料或 service account JSON。

### 學術/商業授權

可行路徑：

- 大專院校 ESG 社會創新沙盒授權。
- 產學合作 proof of concept。
- 長照、醫療、司法、NPO 的隱私轉譯 API。
- 社區發展協會/管委會的系統建置與維護服務。

限制：

- 不得以未審查專利宣稱排除他人權利。
- 不得承諾補助必得。
- 不得把研究資料變成會員個資販售。
- 商業授權收入仍須進入會計窗與公益治理。

## 紅隊風險

| 風險 | 等級 | 防線 |
| --- | --- | --- |
| 幸福幣被誤認為投資商品 | L3 | 非金融化、有效期限、折抵用途、法律/會計審查 |
| 公益池資金私用 | L3 | fail-closed、人類決策、audit、錯帳更正 |
| 分潤比例未經合約 | L3 | 合約窗、會計窗、Odoo manifest |
| AI 自動付款/退款/折扣 | L3 | payment/manager override blocked |
| 社區資料反推個人 | L2/L3 | 小樣本抑制、總量公開、明細不公開 |
| Odoo 權限誤配 | L2 | record rules、role map、no physical delete |
| 政策/補助日期錯用 | L2 | 正式送件前重新查證 |
