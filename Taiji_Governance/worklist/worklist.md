   - community management
   - AI POS
   - AI committee equipment management
   - community scenario applications
   - Odoo Governance Runtime
   - Taiji Gateway / Metric Translation Gateway / Five Metric Gate

3. Inventory existing POS implementations and separate them into governed modules:
   - POS code inventory
   - Odoo POS relation map
   - customer display boundary
   - Sunmi POS boundary
   - non-sensitive demo dataset
   - local-only tests

4. Define authorized AI automation as scoped developer capability:
   - A0 read-only understanding
   - A1 design/documentation
   - A2 local reversible code changes
   - A3 local preflight
   - A4 guarded deployment preparation
   - A5 live operation remains not enabled
   - XiaoJ behavior must pass metric topology gateway alignment before crossing windows
   - human authority and XiaoJ both act as metric guardians, not exceptions above the metric law
   - degree must be treated as tensor calculation, rule as vector calculation, and gateway translation as the action boundary

5. Replace unsafe direct deployment flows with gated deployment manifests:
   - no service account JSON transfer
   - no OAuth token transfer
   - no direct Gemini / Google API call
   - no direct router or VPN mutation outside Gateway policy

6. Establish baseline artifacts:
   - SHA256 manifest
   - rollback manifest
   - audit jsonl
   - runtime snapshot
   - deployment status report

7. Keep command authority separate from secret material:
   - Ultra organization authority may define non-sensitive command policy
   - service-account delegation must be represented as policy metadata only
   - live credentials remain outside repo and outside node deployment payloads
   - natural person identity proof must remain outside repo and outside plaintext audit

8. Model public-benefit value generation without making premature financial claims:
   - carbon-rights or sustainability signals may trigger design proposals
   - proposals must not be treated as guaranteed profit
   - development-fund candidates require legal/accounting/carbon-inventory evidence
   - community beneficiary and public-good purpose must be explicit
   - public assets and fund pools must not be redirected to private profit
   - labor and intellectual contribution may be quantified only through approved, audited compensation rules
   - calculations must align to absolute value invariants, not preset values
   - fund-pool survivability and executable public benefit are baseline constraints
   - value-peak optimization must preserve legitimate contribution compensation
   - finance must use accountant precise window before any formal accounting, tax, payment, carbon-rights, or fund-pool operation

9. Maintain architecture and completion board:
   - update module completion after each verified patch or inventory
   - keep completion as governance-packaging completion, not production readiness
   - show architecture, modules, windows, risks, and next safe work together

10. Build metric predictive alerting:
   - proactively warn developer before likely hazard
   - detect window mismatch, secret risk, cloud plaintext, remote execution, container exposure, finance/accounting drift, public-asset privatization, and developer-laptop-unavailable risk
   - provide ten developer prompts before sensitive work
   - keep first implementation read-only and non-secret

11. Design distributed compute topology:
   - developer laptop remains governance baseline
   - distributed nodes may compute or serve local tools but cannot bypass Gateway/Five Metric
   - laptop poweroff must be handled by snapshots, manifests, audit, and reconciliation
   - POS/display/Odoo/GPU/WebUI nodes require identity and exposure review

12. Design Google Workspace and Odoo no-personal-data mailbox policy:
   - use Google Workspace as organization-policy gateway only after Gateway/Five Metric approval
   - keep Odoo mailbox no-personal-data by design
   - avoid domain-wide delegation unless critical and scoped
   - never read or print service account JSON

13. Design device least-privilege and AI browser UI:
   - each device receives only minimal role capability
   - AI browser control is a constrained user interface
   - high-privilege pages require human review and cannot be auto-submitted
   - browser actions require manifest and redacted audit

14. Verify cognitive-window authority merge safely:
   - highest authority is semantic input only
   - execution privilege is always projected to minimal window
   - sandbox verification precedes implementation
   - red-team review must correct hazards before runtime use

15. Extend development with Odoo as primary scenario system and Google as non-sensitive permission manager:
   - Odoo owns POS/community/device/work-order scenario data
   - Google Workspace owns no-personal-data account/group/OU/policy metadata
   - synchronize only identity/role/permission labels and audit metadata
   - block member plaintext, transaction plaintext, payment sensitive data, personal Gmail body, and service account material
   - preserve separation of duties so no single subsystem dominates
   - cloud/local auto-account bridge must produce request manifest and redacted audit journal

16. Enforce developer-push recommendation format:
   - each pushed alert must include a recommended solution
   - each recommended solution must include impact assessment
   - impact assessment must cover benefit, cost, risk, affected modules, data boundary, permission change, and rollback

17. Evaluate and implement five-dimensional code zero-tree tensor I/O:
   - D1 node identity
   - D2 data sensitivity
   - D3 action intent
   - D4 permission window
   - D5 reversibility and public value
   - first stage is readonly index and bridge manifest only
   - zero branches must not be auto-filled by AI
   - metric assembly must remain mandatory and cannot be deprecated

18. Connect Odoo to Google for Nonprofits mailbox by manifest-first flow:
   - use Google Workspace for Nonprofits no-charge baseline
   - create Odoo no-personal-data system mailbox proposal
   - prefer Google SMTP relay for devices/apps after human admin review
   - keep Enterprise discounted plans out of the free default path
   - write bridge audit journal for every cloud/local auto-account event
   - do not perform live Google Admin or Odoo mail changes before sandbox preflight

19. Build Five-Metric Tensor Runtime as the governance operating layer:
   - represent every executable runtime state as `TensorPacket`
   - enforce intent/resource/time/authority/topology vectors before execution
   - preserve tensor summaries, packet hashes, replay-safe references, topology state, and audit lineage instead of unrestricted plaintext memory
   - add replay governance for prompt, shell, deployment, payment, multimodal, deadbox, and stale topology replay
   - route unsafe packets into tensor deadbox and require authority regeneration, replay reset, audit review, and human approval before re-entry
   - keep distributed nodes subordinate to Gateway/Five Metric and reconciliation rules
   - require human decision for payment execution, production overwrite, destructive deletion, credential issuance, authority escalation, governance override, legal commitment, and external deployment approval

20. Convert runtime reconciliation files into machine-checkable validators:
   - replay index validator
   - TensorPacket schema validator
   - topology trust graph validator
   - deadbox restore gate
   - plaintext-free context scanner
   - AI usage routing policy tests
   - multimodal governance preflight
   - distributed reconciliation dry-run

21. Maintain Multi-Governance Identity architecture:
   - never collapse the owner into a single super-admin identity
   - separate Runtime Owner, System Architect, Community Governor, Technology Sponsor, Runtime Operator, Private Commercial Operator, and Community Industry Operator
   - bind each identity to its own authority vector, audit boundary, data scope, container scope, domain scope, Odoo scope, replay risk, and deadbox policy
   - preserve public/private/commercial/accounting separation
   - keep technology sponsorship and hardware lending traceable without creating public-asset control
