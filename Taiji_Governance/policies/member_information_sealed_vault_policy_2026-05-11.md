# 會員資訊資料庫物理封存政策

版本：2026-05-11  
適用主體：新北市三重區五常社區發展協會  
資訊負責人：江政隆，本會授權之總幹事  
儲存位置：本機 D 磁碟 / 記憶卡會員資訊庫  
模式：建立後物理封存  
生效時點：系統正式交付營運後  

## 開發期狀態

目前 Taiji Hub 處於開發期間。

開發期間無正式會員個資庫，亦無正式會員個資處理問題；目前僅使用本會幹部帳號進行功能測試。

因此，本政策為正式交付營運後之生效條款，不代表目前系統已持有正式會員資訊資料庫。

## 核心規則

會員資訊資料庫建立後即進入物理封存狀態。

封存後不得作為：

- 日常查詢資料庫
- AI 記憶資料庫
- 雲端同步資料庫
- POS/Odoo 即時讀寫來源
- 自然語言直接查詢來源
- 開發測試資料來源

會員資訊資料庫只作為本會受保護資訊之封存基準。

## 唯三開封情境

封存後僅得於以下三種情境開封或查核：

### 1. 會員個人設備遺失或變更

目的：

```text
核對五維碼並註記。
```

限制：

- 僅核對必要欄位
- 僅註記設備遺失或變更狀態
- 不得擴張查詢其他會員資料
- 不得輸出完整會員資料
- 必須留下 audit
- 必須產生封存前後 SHA256

### 2. 中華民國公務機關依法定權限之公文書命令

目的：

```text
依中華民國公務機關具法定權限之正式公文書命令辦理。
```

限制：

- 必須有正式公文書
- 必須確認機關權限
- 必須記錄文號、機關、日期、要求範圍
- 僅提供法定命令要求之最小必要資料
- 必須保存回覆紀錄與 SHA256
- 不得因口頭要求或非正式訊息開封

### 3. 本人主張資料註銷或變更

目的：

```text
處理本人依法或依本會規範主張之資料註銷或變更。
```

限制：

- 必須確認本人主張
- 僅處理該本人資料
- 必須保留變更前後紀錄之 hash
- 必須記錄註銷或變更理由
- 必須保留 audit 與 rollback / correction reference

## 開封流程

```text
開封原因提出
→ 開封情境分類
→ 本人/機關/設備事件核驗
→ 公益度規與法定權限確認
→ 最小必要範圍設定
→ 開封前 SHA256
→ 只讀查核或必要註記
→ 開封後 SHA256
→ audit record
→ 重新物理封存
```

## 禁止事項

以下一律禁止：

- 日常業務查詢會員資訊資料庫
- AI 自行讀取會員資訊資料庫
- 將會員資訊資料庫上傳雲端
- 將會員資訊資料庫接入外部 AI
- 將封存庫作為 Odoo/POS live database
- 未經三種情境之一開封
- 未留 SHA256 與 audit 開封
- 開封後未重新封存

## 五維碼核對

會員個人設備遺失或變更時，僅允許：

- 核對五維碼
- 註記設備狀態
- 記錄事件時間
- 記錄審查者
- 記錄最小必要 hash

不得：

- 輸出完整會員資料
- 查詢無關會員
- 建立新 AI 記憶
- 上傳雲端

## L3 Metric Hazard

以下一律標記 `L3_metric_hazard = block`：

- 非三種情境開封
- 無正式公文書之機關要求開封
- 會員設備事件中查詢超出必要範圍
- 本人資料註銷或變更時處理非本人資料
- 開封後未重新封存
- 開封未留 SHA256 / audit
- 將封存庫用於開發測試或 AI 訓練

## 最終原則

```text
會員資訊資料庫不是便利查詢工具。
會員資訊資料庫是本會受保護資訊之物理封存基準。
只有設備遺失/變更、公務機關依法公文書命令、本人主張註銷或變更三種情境可開封。
每次開封必須最小必要、可稽核、可追溯、重新封存。
```
