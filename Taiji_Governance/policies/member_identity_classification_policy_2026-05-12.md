# 本會會員身分分類治理政策

日期：2026-05-12  
主體：新北市三重區五常社區發展協會  
性質：章程會員身分分類模型，不含會員名冊、不含個資明文

## 目的

本政策將本會章程所定會員身分轉為系統可用的治理分類，供 Odoo 社區主模組、主權 AI 商業用 POS 系統、社區服務、公益研究、會費與權益分窗設計使用。

本文件只定義類型、規則與權限邊界，不建立任何正式會員資料庫，不記載自然人姓名、身分證號、地址、電話、會員編號或個別商家營業明細。

## 會員身分總則

本會會員身分分為：

1. 團體會員
2. 自然人會員

本會職務身分另行分窗，不得與一般會員身分混同。總幹事屬本會治理與執行職務窗口，不是一般會員權益窗口。

自然人會員依所在地與章程資格，分為：

1. 正式會員
2. 贊助會員

團體會員依組織場景，至少包含：

1. 商家
2. 物業 / 管委會
3. 其他經本會章程、理監事會或會員大會授權之團體類型

商家團體會員與物業/管委會團體會員不得混同。商家以主權 AI 商業用 POS、社區產業、商業協力為主要場景；物業/管委會以 AI 管委會、設備管理、社區安全、會議與工單為主要場景。

## 入會明文資料與五維碼原則

每位會員入會時，必要明文資料採物理保管與人類審查流程處理，不作為 AI runtime、雲端資料庫或一般 Odoo 查詢內容。

系統發給會員之五維碼只代表會員權益、資格狀態、服務窗口、治理分窗或不可識別狀態，不代表個資紀錄本身。

原則如下：

1. 五維碼不得保存完整姓名、身分證字號、電話、地址、生日、家庭資料、兒童資料或其他可直接識別個人之明文。
2. 五維碼不得設計成可逆查回自然人明文資料。
3. 個資明文原則上保存在會員自身設備、會員持有文件，或本會經人類審查之物理封存流程。
4. 本會系統只保存五維碼、不可逆 hash、權益狀態、audit reference 與必要治理 metadata。
5. 當會員設備遺失、變更、註銷或依法令公文要求時，才可進入人類審查與物理封存開封流程。
6. 開發期間不得建立正式會員個資庫；只允許 mock 五維碼、測試權益狀態與無敏統計。

五維碼是「會員權益與治理狀態的代表碼」，不是「會員個資資料庫」。

## 會員 AI 端白名單五維碼功能

所有五維碼功能必須依本會組織政策授權後，才可由會員 AI 端調用。會員 AI 端不得因持有五維碼而取得最高權限、會員明文、Odoo 明細、Google 私人資料或會計明細。

白名單判斷必須同時檢查：

1. 五維碼格式與簽章/雜湊狀態有效。
2. 會員身分分類符合該功能允許範圍。
3. 權益狀態未過期、未註銷、未進入 deadbox。
4. 調用端屬於本會授權會員 AI 端或受信設備。
5. 功能屬於組織政策允許的白名單功能。
6. 請求已通過 Gateway / Five Metric Gate / Audit 檢查。
7. 高風險功能仍需人類確認。

白名單功能可包含：

| 功能類型 | 允許內容 | 禁止內容 |
| --- | --- | --- |
| member_status_check | 查詢本人權益狀態、資格分窗、服務窗口 | 反查姓名、電話、地址、身分證字號 |
| community_service_request | 申請社區服務、學童安全專車需求、公共服務協助 | 暴露兒童個資、家庭資料、個人路徑 |
| pos_member_benefit_draft | 產生主權 AI 商業用 POS 會員權益草稿 | 直接付款、折扣 override、交易明細外送 |
| forum_registration_token | 向 Google Workspace 論壇會員流程提供非敏註冊 token | 直接建立 Google 帳號、讀 Gmail、取得 OAuth token |
| odoo_mailbox_request | 申請 Odoo/Google 組織信箱或別名的治理 manifest | AI 直接呼叫 Admin SDK 建帳、輸出 service account JSON |
| audit_receipt_query | 查詢本人相關 audit receipt 或服務狀態 | 查詢他人紀錄或完整資料庫 |

任何不在白名單內的五維碼功能，一律視為 `L2_drift` 或 `L3_metric_hazard`，需阻擋或進入人類審查。

## Odoo / 系統設計規則

1. Odoo 可建立「會員身分類型」與「資格判斷欄位」的模型草稿。
2. 開發期間不得匯入正式會員明文資料。
3. 團體會員與自然人會員必須使用不同資料表/模型分窗，避免商家資料、管委會資料與自然人資料混用。
4. 商家團體會員與物業/管委會團體會員必須使用不同服務模型、權限、帳冊與 audit 分窗。
5. 總幹事、理監事、會務人員等治理職務不得被表示為一般會員權益；職務行為必須走治理/執行/審核窗。
6. 轄區內外資格只可作為分類因子，不得在無必要時保存完整地址明文。
7. 正式會員與贊助會員的權利義務差異，需由章程與本會治理程序決定，不得由 AI 自行擴權。
8. 主權 AI 商業用 POS 系統只能使用團體會員或場景服務所需的最小資料。
9. 公益帳務、會費、社區產業收入與團體會員營業資料必須分窗稽核。
10. 團體會員與分公司均應開立獨立會計帳冊，不得與本會公益總帳、其他團體會員帳冊或自然人會員資料混帳。
11. 各獨立帳冊只可向本會總資料庫提供「總類科目」與「總數字」之不可逆映射；不得提供可讀營業摘要、個別營業明細、會員明文或可逆交易細節。
12. 單店層級只做「營業總額」紀錄，不公開、不上雲、不提供 AI 讀取單店營業摘要內容。
13. 本會總帳可見公開科目與總量數字；個別團體會員或分公司帳冊之明細與摘要均屬商業機密，須依權限、audit、會計分窗與人類審查存取。

## 分公司與團體會員會計帳冊規則

| 主體類型 | 帳冊規則 | 可彙總內容 | 不可彙總內容 |
| --- | --- | --- | --- |
| 團體會員 | 獨立會計帳冊 | 總類科目、總數字、不可逆統計 | 個別營業明細、可讀營業摘要、會員明文、商業機密 |
| 分公司 | 獨立會計帳冊 | 總類科目、總數字、不可逆統計 | 分公司營業摘要、未授權交易明細、員工/會員個資、金流敏感明文 |
| 單店 | 營業總額紀錄 | 單店營業總額 | 品項明細、營業摘要、客戶/會員資訊、交易細節 |
| 社區總量市場 | 多店總量統計 | 全社區品類總量、總金額、不可逆市場趨勢 | 單店品項銷售、單店明細、可反推單店營業結構之資料 |
| 不可識別人口統計 | 群體分布統計 | 年齡區間比例、性別比例、消費額度比例 | 購買者身分、單人交易、可回推個人之交叉欄位 |
| 不可識別時間桶市場熱度 | 時段總量統計 | 幾點生意最好、時段總交易額、時段品類總量 | 某人在某時買了什麼、單店細目、可追蹤個人路徑 |
| 公共服務需求訊號 | 社區治理可見訊號 | 上班車潮時段、學童安全社區專車需求、公共服務缺口 | 個人行蹤、兒童個資、家庭資料、可識別路徑 |
| 會員五維碼 | 非個資代表碼 | 權益狀態、資格分窗、服務窗口、audit reference | 可逆個資索引、會員明文、自然人完整資料 |
| 會員 AI 端白名單 | 組織政策授權功能 | 本人狀態、服務申請、論壇註冊 token、Odoo 信箱 manifest | 任意 API、Admin SDK 直呼、他人資料、secret |
| 社區產業基金本體店 | 五常社區數位發展基金本體帳冊 | 基金本體總額、總類科目、公益用途總量 | 私人資本利得分配、可讀營業摘要、未授權交易細節 |
| 本會主公司 | 公益總帳與公開科目總量 | 公益收入/支出類科目總數字、基金池總額、治理 audit | 個別團體會員帳冊明細、單店營業摘要、自然人會員明文 |

會計分窗必須滿足：

- 獨立帳冊。
- 獨立權限。
- 獨立 audit。
- 可回滾調整紀錄。
- 可向本會總帳提供不可逆總類科目與總數字。
- 單店只可映射營業總額。
- 社區總量市場可映射品類總量與總金額，但不得可逆回推單店品項或單店明細。
- 人口統計只可使用不可識別群體分布，例如年齡區間、性別比例、消費額度比例；不得知道誰買了該品項。
- 時間桶市場熱度只可知道幾點或哪個時段大家生意最好，不得知道誰在該時段買了哪些品項。
- 公共服務需求訊號可供本會本地治理使用，例如幾點會出現上班車潮、居民需要學童安全社區專車；但不得保存個人行蹤、兒童個資、家庭資料或可識別路徑。
- 本會本地治理可見的公共訊號，不等於雲端可見。雲端只可接收無敏總量、hash、事件代號、匿名狀態與 audit reference。
- 會員五維碼可代表會員權益與治理狀態，但不得作為個資紀錄、不得可逆反查自然人明文。
- 會員 AI 端只能調用組織政策授權的白名單五維碼功能；白名單外功能預設封鎖。
- 不可讓 AI 自動調帳、核銷、付款或修改正式會計結果。

## 單店與社區總量範例

以五常社區仁義商圈早餐業市場集中型態為例：

- 單店層：系統只可知道某單店今天營業總額，例如 `50,000 TWD`。
- 單店層禁止：知道該單店賣了哪些品項、各品項數量、各品項金額、客人明細或可推回商業策略的摘要。
- 社區總量層：系統可知道全社區某品類總量，例如全社區共售出 `120` 個漢堡、總金額 `100,000 TWD`。
- 社區總量層要求：統計必須跨足夠多店、不可逆、不可反推出任一單店營業結構。
- 人口統計層：系統不知道誰買了漢堡，但可知道不可識別分布，例如 `50-60 歲占消費額度 8%`、`男性 65% / 女性 35%`。
- 人口統計層要求：不得與時間、地點、單店、付款、會員或裝置資料交叉到可識別個人。
- 時間桶市場熱度層：系統可知道例如 `07:00-09:00` 是早餐市場高峰，或某時段全社區營業額最高。
- 時間桶市場熱度層禁止：知道某個自然人、會員或裝置在該時段買了哪些品項，也不得將時間桶與人口統計交叉到可識別個人。
- 公共服務層：系統可知道例如上班車潮尖峰、學童安全社區專車需求、接送服務缺口或社區交通壓力。
- 公共服務層要求：本會本地治理窗可見，雲端不可見明細；雲端只保存不可識別總量指標。

此規則是無明文上下文的會計/商業資料版本：只見總量市場訊號，不見單店商業機密。

## 禁止事項

以下均為 `L3_metric_hazard`：

- 將會員身分分類模型直接當作正式會員名冊。
- 開發期間匯入正式會員個資明文。
- 將總幹事、理監事、會務人員等治理職務混同為一般會員權益窗口。
- 將商家團體會員資料與物業/管委會團體會員資料混用。
- 將自然人會員個資交給團體會員或商家使用。
- 將團體會員營業機密公開到組織唯讀雲端。
- 將團體會員或分公司獨立帳冊混入本會公益總帳明細。
- 將單店營業摘要、品項明細、交易細節或商業機密作為可讀資料送入總資料庫或雲端。
- 以社區總量資料反推任一單店品項、單店營業結構或商業策略。
- 以年齡、性別、時間、地點、付款或會員資訊交叉重建個別購買者。
- 以時間桶資料追蹤個人消費路徑、個人品項偏好或單店交易細目。
- 將上班車潮、學童接送、安全專車需求中的個人路徑、兒童資訊或家庭資訊送往雲端。
- 將「協會本地可見」誤升級為「雲端可見」。
- 將會員五維碼設計成可逆個資索引。
- 將會員設備中的個資明文同步到雲端或 AI runtime。
- 在未經人類審查與物理封存流程下，要求系統讀取會員設備內的個資明文。
- 會員 AI 端繞過組織政策白名單、Gateway、Five Metric Gate 或 audit。
- 會員 AI 端以五維碼直接呼叫 Google Admin SDK、Gmail API、Odoo production write 或付款功能。
- 將社區產業基金本體店之帳冊轉作私人資本利得或私人分配。
- AI 未經會計分窗與人類審查自動調帳、付款、核銷或改寫正式帳冊。
- AI 自動判定正式會員資格並給予章程權利，未經人類審查。
- 使用會員身分繞過 Five Metric Gate、Taiji Gateway、Audit 或人類決策。

## 開發期狀態

目前狀態：分類模型可用，正式會員資料庫未啟用。

開發期間可使用：

- 測試帳號
- mock member class
- 無敏統計
- 去識別資格狀態
- 團體會員範例資料

開發期間不可使用：

- 正式會員名冊
- 自然人完整個資
- 可逆會員五維碼
- 未審查的 D 磁碟會員封存庫
