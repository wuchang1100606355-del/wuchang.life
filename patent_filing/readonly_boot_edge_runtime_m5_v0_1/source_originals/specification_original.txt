一種基於唯讀啟動媒體之邊緣運算執行環境注入、瞬態記憶體調度與執行狀態回滾方法
一、發明名稱
一種基於唯讀啟動媒體之邊緣運算執行環境注入、瞬態記憶體調度與執行狀態回滾方法。
二、摘要
本發明涉及一種在邊緣運算設備上利用唯讀啟動媒體注入執行環境的方法。該方法透過唯讀啟動媒體啟動節點，從媒體中的使用者資料與環境設定檔擷取參數，注入並配置執行環境，並於揮發性記憶體建立瞬態 tmpfs I/O 區作為運行期間的暫存空間。應用程式在該執行環境內運行並將暫存數據寫入該 I/O 區，同時稽核日誌模組記錄事件與環境變數。運行結束後系統透過回滾模組釋放 tmpfs 區並還原環境參數，確保啟動媒體保持唯讀且無持久修改，提供安全、可複製且易於部署的邊緣運算執行環境。
三、技術領域
本發明屬於計算機工程領域，特別是關於在邊緣運算設備上利用唯讀啟動媒體進行執行環境注入與瞬態記憶體管理的技術，涉及環境參數擷取、執行環境注入、瞬態記憶體調度、稽核日誌以及執行狀態回滾。
四、先前技術
傳統的邊緣運算節點大多依賴可寫入的本地儲存媒體或持久性檔案系統來部署程式與配置參數。這些系統通常需要事先安裝作業系統和軟體套件，並透過編輯設定檔來注入環境變數。當節點需要更新時必須重新部署或手動調整設定，既耗時又容易出錯。此外，依賴持久性儲存也增加了系統遭受惡意修改或意外損壞的風險。另一方面，一些容器化解決方案支持環境變數注入，但仍依賴完整的作業系統映像且缺乏完整的回滾機制，也未針對邊緣環境的記憶體限制設計瞬態 I/O 流程。
五、發明內容
本發明提出一種透過唯讀啟動媒體注入邊緣運算執行環境並提供瞬態記憶體調度與執行狀態回滾的方法。其流程如下：首先利用唯讀啟動媒體啟動邊緣節點，該媒體包含最小化的作業系統與啟動腳本。啟動後，環境參數擷取模組從「user-data」、「global_env.env」以及「/etc/taiji_global.env」等設定檔中解析環境變數，並與「/etc/profile」中的系統變數合併。隨後，執行環境注入模組根據擷取的參數動態修改「docker-compose.yml」或其他協調檔案以啟動容器化執行環境，並在注入過程中建立各服務所需的環境。為避免對硬碟造成寫入，本發明於揮發性記憶體建立瞬態 tmpfs I/O 區作為應用程式的工作目錄，所有暫存檔案與輸出皆寫入此區域。應用程式運行期間，稽核日誌模組會將環境注入紀錄與運行事件寫入稽核檔案（例如「audit log」與「taiji_boot.log」）。運行結束後，回滾模組清除 tmpfs 區並還原所有環境變數至啟動狀態，以維持唯讀啟動媒體的不變性，確保每次啟動時都能取得一致且乾淨的執行環境。此方法不僅提升了部署效率與安全性，還能減少記憶體與儲存的消耗，適合在資源受限的邊緣節點上使用。

七、符號說明
八、實施方式
以下以一具體實施例說明本發明的方法。首先，將包含「taiji_bootstrap.sh」與必要配置檔的唯讀啟動映像燒錄至啟動媒體，並將啟動媒體插入邊緣裝置。啟動後，啟動腳本執行環境參數擷取程序，依序讀取「user-data」中的使用者自訂參數、「global_env.env」與「/etc/taiji_global.env」中的全域環境設定，以及「/etc/profile」中的系統預設變數，依權重順序合併成完整的環境設定。接著，程式根據合併後的變數修改「docker-compose.yml」，例如將環境變數注入到容器服務的 environment 區段，並啟動所需的容器。若運行於 Windows 平台，則會執行「Activate.ps1」和「openssl_deactivate.ps1」腳本以載入或關閉特定功能。在容器啟動階段，系統會在記憶體中建立 tmpfs 掛載點作為瞬態 I/O 區，所有服務的日誌與暫存檔案皆寫入該區域。運行過程中，稽核日誌模組即時收集環境注入紀錄、系統事件與錯誤，寫入「audit log」與「taiji_boot.log」。當應用程式退出或收到終止訊號後，回滾模組會關閉容器、卸載 tmpfs、移除注入的環境變數並還原系統狀態。如此即可確保啟動媒體保持唯讀，也能在每次啟動時提供一致的執行環境，並透過稽核日誌追蹤每次執行的細節。
