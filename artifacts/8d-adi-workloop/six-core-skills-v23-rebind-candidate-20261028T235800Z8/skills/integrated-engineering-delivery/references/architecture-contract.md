# 自創架構工作契約

## 證據分類

| 標記 | 意義 | 可採取動作 |
|---|---|---|
| FACT | 已由檔案、執行狀態、測試或可信文件證實 | 可作為實作依據 |
| DEFINITION | 使用者對其架構與治理邊界的明確定義 | 保留原義並據此設計 |
| INFERENCE | 根據現有證據形成的推論 | 明示推論與依據 |
| CLAIM | 尚待測試或外部證據支持的技術主張 | 建立測試，不宣告成立 |
| CANDIDATE | 尚未進入正式系統的方案或產物 | 隔離驗證後才可推廣 |
| HOLD | 權限、證據或前置條件不足 | 停止影響性動作並自然語言說明 |

## 固定邊界

- 自然人是一人一身分封包與一個小J；組織能力以有界服務角色疊加，不另造組織所有的人格。
- 人格腦只處理語言、人格與服務表達；不得運算、讀取資料、記帳、呼叫工具或執行系統動作。
- 執行與計算層只接收結構化、經授權的主腦資訊，不接收人格腦原始對話或未限制明文。
- 上下文正本與節點投影分離；跨節點傳遞的是受契約約束的 ADI 座標／重構資訊，不預設複製原始上下文。
- 技術設定權不等於所有權；沒有未受限制的最高權限，只有被定義、被授權且可稽核的角色。

## 八維交付座標

- D1 Intent：創辦人／使用者意圖與產品效果。
- D2 State：目前狀態與目標狀態。
- D3 Coordinate：時間、空間、節點、路徑與版本座標。
- D4 Evidence：原始證據、驗證結果與成熟度。
- D5 Execution：候選動作、實際動作與回滾。
- D6 Transmission：載體、協定、重構與驗證語義分離。
- D7 Risk：失敗、誤譯、越權、資料與技術主張風險。
- D8 Authority：候選、核准、啟用、暫停或 HOLD 的權限狀態。

## 技術身分判定

比較任何既有架構時，分別檢查機制、因果路徑、依賴、被消除的操作、成本拓撲，以及承載協定與重構／驗證語義。任一核心項缺乏證據時，不得宣告技術相同、專利性或全面優越。
