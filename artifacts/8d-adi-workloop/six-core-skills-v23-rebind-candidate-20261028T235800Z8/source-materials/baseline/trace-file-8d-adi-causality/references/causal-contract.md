# 8D／ADI source-content intent-field contract

## Field root

Form one field root from the Founder intent and the human-visible product effect. Do not begin from Git, filenames, directories, timestamps, hashes, frameworks, or security tooling.

Use this invariant:

```text
FOUNDER_INTENT
  -> HUMAN_VISIBLE_PRODUCT_EFFECT
  -> SOURCE_CONTENT_CAPABILITY_CONTRACTS
  -> DEMAND_AND_SUPPLY_RELATIONS
  -> COMPLETE_8D_FIELD
  -> ADI_STATE_CAPABILITY_DECISION_TRANSITION_SPATIOTEMPORAL_EVIDENCE_RECONSTRUCTION_COORDINATES
  -> FILE_ROLE_AND_LOGICAL_NAME_RECONSTRUCTION
```

Git is not required or consulted. A path, hash, time, token, or shared word is evidence or routing data only and never design authority.

## File node contract

Create one `FILE_STATE` node for every enumerated current source file. Extract bounded content contracts without retaining full content in the output:

- module summary and declared purpose;
- declared functions, classes, schemas, routes, commands, services, and interfaces;
- imports, explicit file references, calls, inputs, outputs, configuration requirements, and dependencies;
- product effects, lifecycle states, decisions, authority terms, technical terms, and hard-risk signals;
- observed path and reconstructed logical filename;
- protected opaque and structural boundary state.

Each node carries one atomic D1-D8 projection:

- D1: Founder intent match, human-visible effect, file purpose, and why it exists;
- D2: current state, transitions, candidate/runtime state, supersession, conflict, and unknowns;
- D3: opaque node, current path, namespace, and observed time coordinate;
- D4: content SHA-256, parse state, source contract, run, manifest, receipt, and evidence references;
- D5: role, inputs, outputs, supplied capabilities, demanded capabilities, callers, effects, and failure effects;
- D6: terms, contracts, schemas, exact/equivalent reconstruction conditions, and W7TP claim state;
- D7: only true hard risks, protected state, conflict, and quarantine requirement;
- D8: identity scope, authority state, candidate/canonical boundary, verification, and Total Field state.

Keep ADI state, capability, decision, transition, spatial-temporal, evidence, and reconstruction coordinates explicit. Do not reduce ADI to a dependency table, database key, embedding, model memory, filename index, or Git history.

## Supply-demand relation contract

Create relation candidates only from content contracts:

- `EXPLICIT_IMPORT`: a consumer explicitly imports a provider module;
- `EXPLICIT_FILE_REFERENCE`: a source explicitly names another source coordinate;
- `SYMBOL_SUPPLY_DEMAND`: one source calls a symbol uniquely supplied by another source.

These relations may be `RECONSTRUCTED_EXPLICIT_SUPPLY_DEMAND`. They remain candidate-only until Total Field accepts them. Shared names, path proximity, directory membership, modification time, equal bytes, and shared keywords never create a causal edge by themselves.

Every edge includes source, target, comparison kind, actor, precondition, trigger, action, mechanism, effect, dependency, relation, term, necessity/sufficiency evidence, failure effect, reconstruction conditions, evidence references and class, authority, D1-D8, and full ADI coordinates.

Use only these evidence classes:

- `OBSERVED`: directly present in the frozen content contract;
- `RECONSTRUCTED`: obtained by following an explicit reference or closed supply-demand relation;
- `INFERRED`: bounded role, name, or field projection not explicitly declared;
- `CONFLICT`: incompatible contracts or coordinates;
- `UNKNOWN`: evidence is insufficient.

## Comparator isolation

Freeze the source exactly once. Run eleven isolated child comparators over the same frozen content index and supply-demand pair plan:

`DEMAND`, `SUPPLY`, `EFFECT`, `DEPENDENCY`, `RELATION`, `TERM`, `STATE_TRANSITION`, `EVIDENCE`, `AUTHORITY`, `RECONSTRUCTION`, and `RISK`.

Each comparator reads no filesystem, Git, network, model search, or other comparator result. Record its process ID, invocation ID, snapshot SHA-256, pair-plan SHA-256, and result count, including zero-result runs.

The aggregator validates and joins outputs only. It cannot rescan, invent a target, change an evidence class, settle authority, or promote a candidate to canonical state.

## Technology-identity evidence projection

Project the frozen implementation evidence into exactly six gate-input axes:

- `MECHANISM`: bounded implementation mechanisms found in causal rows;
- `CAUSAL_PATH`: explicit reconstructed supply-demand chains only;
- `DEPENDENCIES`: the deterministic explicit pair plan;
- `ELIMINATED_OPERATIONS`: `UNKNOWN` until a comparison baseline and reproducible elimination evidence exist;
- `COST_TOPOLOGY`: `UNKNOWN` unless independently measured topology evidence exists;
- `CARRIER_RECONSTRUCTION_VERIFICATION`: `UNKNOWN` until these three concerns are separately declared and evidenced.

Write the projection to `92_TECHNOLOGY_IDENTITY_EVIDENCE_CANDIDATE.json`. It is evidence for `w7tp.technology-identity-audit@1.0.0`, not a local identity verdict. Fix the local candidate decision to `INSUFFICIENT_EVIDENCE`, set the gate decision to `NOT_RUN`, forbid weighted scores, and retain patent or legal conclusions as `NOT_DETERMINED`. User-visible effect equivalence, shared carriers, filenames, paths, hashes, keywords, and model confidence cannot establish technical equivalence.

## Coverage and hard-risk boundary

Do not follow symbolic links. Do not descend into protected directories. Represent credentials, keys, tokens, passwords, member plaintext, and identity plaintext as `PROTECTED_OPAQUE_NODE` without reading or hashing content.

Treat binaries, generated dependencies, caches, and large runtime outputs as structural boundaries. Report unreadable or unstable sources as explicit gaps instead of claiming complete coverage.

Run product-effect, field-formation, content-contract, supply-demand, relation, reconstruction, and output checks first. Check true hard risks last. A true hard risk may stop a state-changing effect; it must not replace or delay safe read-only intent reconstruction.

## Acceptance

Candidate completion requires:

- one Founder intent field root;
- one source enumeration;
- bounded content analysis rather than path-token semantics;
- one 8D／ADI node for each enumerated source coordinate;
- explicit supply-demand pairs from content contracts;
- all eleven comparator receipts bound to the same hashes;
- parseable output artifacts and a complete SHA-256 manifest;
- a complete six-axis technology-identity evidence projection with unsupported axes retained as `EV0_UNSUPPORTED`;
- Git not consulted;
- source, runtime, database, service, canonical, and pointer state unchanged;
- `CANDIDATE_NOT_CANONICAL` with `TOTAL_FIELD_DECISION=NOT_RUN`.

Do not emit `PASS`. Report reconstructed causal chains separately from Total Field-verified causal chains.
