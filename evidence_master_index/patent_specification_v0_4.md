# 發明說明書 v0.4

## 發明名稱

一種基於多維狀態封包之跨系統人工智慧任務執行治理系統及方法

## 技術領域

本發明係有關於一種人工智慧任務執行治理技術，尤指一種應用於企業資源規劃系統、組織帳號系統、通訊平台及邊緣運算節點之跨系統人工智慧任務執行治理系統及方法。

本發明不以大型語言模型、檢索增強生成、意圖驅動網路或一般代理人路由技術本身作為保護核心，而係針對人工智慧產生之候選操作意圖，在觸發外部系統操作前，進行多維狀態封包化、陣型工作區映射、策略閘道判斷、受控連接器執行及稽核回放。

## 先前技術

企業資源規劃系統、組織帳號系統、通訊平台及邊緣運算節點逐漸導入人工智慧代理人或自然語言操作介面。此類人工智慧代理人可依使用者請求產生操作建議、查詢資料或呼叫工具。

然而，當人工智慧代理人可接觸企業資料、帳號服務、通訊平台或邊緣節點時，若僅依賴提示詞、一般權限設定、代理人主題設定或檢索資料來源限制，可能產生下列問題：

1. 人工智慧模型產生之候選意圖可能超出使用者實際授權範圍。
2. 人工智慧代理人可能透過工具呼叫間接觸發外部系統操作。
3. 跨系統操作缺乏一致之操作前授權判斷。
4. 被拒絕、降級、警告或允許之操作難以完整稽核回放。
5. 不同系統之身分、資料來源、工具、工作區及時間狀態缺乏共同封包格式。

因此，需要一種在人工智慧候選意圖進入外部系統操作前，能以可驗證資料結構與策略閘道進行控制之治理架構。

## 發明內容

本發明提供一種跨系統人工智慧任務執行治理系統及方法。該系統將自然語言請求或系統任務請求所產生之候選操作意圖，轉換為多維狀態封包。該多維狀態封包至少包含身分欄位、工作區欄位、資料來源欄位、工具欄位、目標系統欄位、時間欄位及權限尺度欄位。

系統再依該多維狀態封包映射一受控工作區。每一受控工作區對應資料來源集合、工具集合、外部系統連接器集合及稽核規則集合。

於任何外部工具呼叫前，策略閘道模組比對該多維狀態封包、受控工作區及策略資料表，產生 allow、warn、block 或 rollback 之執行判斷。僅於判斷為 allow 時，跨系統連接器模組方得呼叫企業資源規劃系統、組織帳號系統、通訊平台或邊緣運算節點之受限工具。

稽核回放模組記錄自然語言請求或系統任務請求、候選操作意圖、多維狀態封包、受控工作區、策略判斷、工具呼叫內容及結果，以供後續稽核、回放、封存或責任定位。

## 技術效果

本發明至少具有下列效果：

1. 將人工智慧產生之候選操作意圖與實際外部系統操作分離。
2. 於工具呼叫前建立非繞越式策略閘道。
3. 以多維狀態封包統一跨系統操作上下文。
4. 以陣型工作區限制資料來源、工具集合及外部連接器。
5. 對 allow、warn、block、rollback 產生稽核紀錄。
6. 使跨企業資源規劃系統、組織帳號系統、通訊平台及邊緣節點之人工智慧操作具備可稽核、可回放及可封存特性。

## 實施方式

於一實施例中，企業資源規劃系統可包含 Odoo；組織帳號系統可包含 Google Workspace；通訊平台可包含 LINE 或論壇系統；邊緣運算節點可包含本地人工智慧 runtime、本地狀態快取或受控執行節點。

於一實施例中，候選意圖產生模組可由本地模型、雲端模型或規則式程序產生候選操作意圖。該候選操作意圖不得直接呼叫外部系統工具。

於一實施例中，多維狀態封包產生模組將候選操作意圖轉換為包含身分、工作區、資料來源、工具、目標系統、時間及權限尺度之封包資料結構。

於一實施例中，策略閘道模組可依策略資料表產生 allow、warn、block 或 rollback 判斷。當判斷為 block 時，跨系統連接器模組不得呼叫外部工具，並由稽核回放模組記錄該阻斷事件。

於一實施例中，稽核回放模組可將候選操作意圖、多維狀態封包、策略判斷、工具呼叫內容及結果寫入稽核紀錄，並與檔案清單、雜湊清單或證據封存包建立關聯。
