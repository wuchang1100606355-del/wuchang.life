# ADI 段落映射與缺口導向讀取

## 目的

先用低成本座標建立整體地圖，再只讀缺口相鄰段落。不得為了「可能有用」全面展開整個專案。

## 四層讀取

1. `路徑層`：路徑、大小、時間、追蹤狀態，不讀內容。
2. `輪廓層`：安全檔案的標題、頂層結構鍵、匯入、函式與入口名稱，不輸出正文或值。
3. `缺口層`：只讀斷裂關係兩端的必要段落與直接引用。
4. `驗證層`：只讀判定閉環所需的結構、測試、收據與權威段落。

每升一層都記錄理由、範圍、讀取量與停止條件。未獲得足夠理由不得升層。

## 段落座標

```json
{
  "node": "節點",
  "root": "實際根目錄",
  "revision": "版本或快照",
  "path": "相對路徑",
  "segment_kind": "標題／結構鍵／類別／函式／入口／測試／證據",
  "segment_id": "穩定名稱",
  "line_start": 1,
  "line_end": 1,
  "content_digest": null,
  "observed_at": "含時區時間",
  "read_level": "路徑／輪廓／缺口／驗證"
}
```

沒有內容雜湊時，座標只能作觀察定位，不得宣告內容身分固定。

## 整體地圖

先選最多量且最具樞紐性的安全入口：正式索引、結構定義、清單、程式入口、路由、測試索引與權威指標。建立：

```text
上游段落座標 → 關係 → 下游段落座標
```

優先處理：

- 沒有來源的必要需求。
- 沒有消費者的宣稱供給。
- 版本或權威互相衝突的同一能力。
- 程式碼閉環中斷的一環。
- 高擴散半徑但證據等級低的節點。
- 多群組共同依賴的樞紐節點。

## 缺口導向展開

只在下列情況增加讀取：

- 必要關係仍是推論，且直接段落可把它提升為已證明或反證。
- 程式修改的影響傳播到未知邊界。
- 結構、實作、測試、接線、效果或權威座標不一致。
- 兩個節點宣稱同一正式能力。
- 下一個修正動作無法由現有證據唯一決定。

每次只沿一條最短證據路徑展開。讀完後立即重算地圖；缺口已閉合就停止，不連帶全文閱讀。

## 資源預算

預設：

- 第一輪最多 8 個樞紐檔案。
- 每檔先讀輪廓，不超過 64 KiB。
- 每個缺口一次最多展開兩端各一個必要段落。
- 同一閉合群組不重讀；以座標與版本快取結論。
- 超過預算仍未閉合時輸出 `資源預算用盡_缺口仍開放`，列出下一個最有資訊增益的段落。

## 防誤判

- 未讀不等於不存在。
- 截斷輪廓不等於完整檔案結構。
- 標題、鍵名或函式名只證明定位，不證明功能生效。
- 動態載入、生成碼、外部服務與人工流程必須保持未知邊界。
- 敏感路徑只保留中繼資料，不進入輪廓層。
- 不把正文、秘密值、會員明文或私有技術內容送往外部服務。
