# 跨節點 ADI 狀態場

## 對齊方式

每個節點以相同 `logical_root_id` 表示同一邏輯專案，另記：

- `node_id`：由操作者或節點治理明確指定，不只依賴主機名稱。
- 實際根目錄：只作節點內觀察座標，可在不同作業系統使用不同路徑。
- `adi_path_key`：相對路徑經正斜線、Unicode NFC 與明確大小寫模式正規化後的比較鍵。
- 版本、內容雜湊、證據強度、觀察時間及封印。

## 比較結果

- `兩端共有且強一致`：兩端都有相同完整內容雜湊。
- `兩端共有但僅中繼資料一致`：不能證明內容一致。
- `內容分歧`：同一 ADI 比較鍵的完整內容雜湊不同。
- `節點單邊存在`：只證明本次快照在一端觀察到，不能直接判定另一端應刪除或補齊。
- `平台差異`：檔案模式、換行、大小寫、Unicode、符號連結或平台生成物差異。
- `座標衝突`：正規化後不同原生路徑落到同一比較鍵，立即保留。
- `權威衝突`：不同有效權威對同一座標給出互斥決定，立即保留。

## 禁止推論

- 較新時間不等於較新因果或正式版本；節點時鐘可能漂移。
- 檔案較多、分支名稱主要、版本號較大或遠端存在不構成權威。
- 一端沒有觀察到不等於全域不存在。
- 相同雜湊只證明內容一致，不證明來源、作者、權威或效果。
- 跨節點差異不自動觸發複製、刪除、覆蓋、推送、部署或啟用。

## 傳輸邊界

節點間預設只傳送：狀態快照、標準雜湊、最小封印與生成式傳輸封包。分析報告由接收端在記憶體重建，不持久化。

若某路徑只具中繼資料證據，跨節點傳輸封包必須保留 `內容一致性未知`。不得為了補證據而盲目讀取或傳送秘密、會員明文或私有技術內容。

## 比較前提

- 相同邏輯根識別。
- 相同路徑大小寫模式與座標正規化版本。
- 可比較的掃描範圍、深度與排除規則。
- 兩份快照 SHA-256 驗證通過。
- 各節點狀態在掃描期間未漂移。

任一前提不成立時輸出保留，仍可展示已觀察差異，但不得宣告兩節點已同步。
