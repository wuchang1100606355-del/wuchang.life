# 變更送達、先後與主線分支判定

## 基本單位

版本系統實際送達的是提交與分支可達歷史，不是單一檔案。先把檔案依同一契約、實作、消費者、測試、接線、證據與回復邊界組成「可獨立驗證的變更群組」，再為每個群組建立一筆提交候選。

不得為了讓部分檔案看起來乾淨而拆斷程式碼閉環；也不得把無關任務、不同權威或不同回復邊界混成一筆提交。

## 每個變更群組的固定判定

每組都必須輸出：

- 變更群組識別
- 精確包含路徑與明確排除路徑
- 閉環狀態及第一個斷點
- 判定：該推送／不得推送／保留待決
- 送出節點
- 目標遠端
- 目標線路：主線／整合分支／候選分支／隔離保留
- 順序號與前置群組
- 驗證、權威、回復與遠端政策證據
- 解除保留的下一個精確動作

若目標為 GitHub，再增加：候選宣告 SHA-256、base commit、實際 head/tree、PR、review、required check、workflow run、artifact attestation、合併、release 與 Total Field D8 的分離狀態。完整套用 [github-causal-delivery.md](github-causal-delivery.md)，不得用單一綠色 check 壓扁這些狀態。

## 不得推送

命中任一項即不得推送，且不得拖住其他已閉合群組：

- 實際包含原始金鑰、權杖、密碼、會員明文、完整私有查表、權重、相位映射或真正 WHY_IT_RUNS 技術內容。
- 原始失敗訊息負載、暫存、快取、執行輸出、編輯器垃圾、無來源大型二進位或其他不屬於版本歷史的產物。
- 其他任務或其他操作者的變更，未取得納入授權。
- 需要刪除、覆蓋、搬移或降權，但沒有明確授權與可驗證回復路線。
- 已知會破壞目前正式介面，且沒有相容過渡或同一正式切換計畫。

只有檔名、變數名或文件敘述含敏感字樣，不足以判定不得推送；必須依真實內容類型與治理邊界判定。

## 保留待決

命中任一項先保留，不得猜測：

- 變更群組閉環未完成、精確測試失敗或必要負面案例未驗。
- 上游契約、生成來源、權威指標或回復路線未知。
- 目標遠端或遠端政策不明、多個遠端互相衝突，或只能看到可能過期的本機追蹤參照。
- 主線身分只由分支名稱、預設遠端指標、時間較新或節點自述推得。
- 相依圖有循環、跨儲存庫前置未送達，或跨節點同一變更內容分歧。
- 工作樹、版本、索引或觀察座標在分析期間改變。

## 可推送條件

同時滿足才可標示該推送：

1. 群組邊界精確且不夾帶無關變更。
2. 程式碼閉環已閉合，或未適用環節有直接證據。
3. 精確正向、負向與差異檢查通過。
4. 不含真實高風險內容及不該版本化的執行產物。
5. 生成來源、結構、消費者、回復及相容性已對齊。
6. 目標遠端、送出節點與目標線路有明確政策或操作者授權。
7. 所有前置提交已在同一送達集合較早位置，或有可重驗的遠端包含收據。

「可推送」是準備度判定，不等於已授權執行推送。

## 主線與分支

主線不是由 main、master、目前分支或遠端預設名稱自動決定。必須有專案治理、保護規則、正式權威指標或操作者明確指定。

只有下列條件全部成立才列主線候選：

- 正式而非候選技術語意。
- 完整閉環、相容路線與回復路線成立。
- 無未解保留、權威衝突或跨節點分歧。
- 主線納入方式符合保護與審查政策；若禁止直接送入主線，目標應為整合分支，再由正式審查納入。

候選、實驗、影子、未完成遷移、等待權威核准或需多節點對齊者，送往明確的候選或整合分支。真實高風險、來源不明或污染產物只隔離保留，不建立可推送分支作為規避。

GitHub Pull Request 是可審查的送達與討論座標，不是因果、權威或執行效果。required check 只證明指定檢查對指定 commit 回報成功；若 check 沒有綁定候選宣告、完整 diff、群組閉合與 D8 收據，不得據此宣告可以合併或正式生效。

## 先後順序

先由需要關係建立有向圖，再做拓撲排序。每一條「甲需要乙」都要求乙先於甲送達；排序不能完成時輸出相依循環保留。

一般安全順序是：

1. 向後相容的權威契約、結構定義與擴充介面。
2. 能同時理解舊新契約的供給端與純核心。
3. 轉接器、消費者與跨節點相容接線。
4. 經證據核准的正式切換指標。
5. 舊路徑停用或移除，必須另有刪除授權。

測試、負面案例、驗證器與最小文件應跟隨它們證明的變更群組，不得永遠排在程式之後形成無驗證中間狀態。

若有相容性循環，使用「先擴充、再遷移、後收縮」拆成多個可獨立通過的群組；任何一步無法單獨安全存在時，整組保留。

## 跨節點與多遠端

- 同一邏輯變更以內容雜湊、父版本、邏輯根及 ADI 座標辨識，不靠檔名或時間。
- 總場依正式權威證據選定唯一送出節點；其他節點只提供交叉驗證，避免重複或互相覆蓋推送。
- 目標遠端優先使用明確的分支送達設定、專案政策或操作者指定；origin 等名稱本身不代表正確遠端。
- 未連線查證時，只能說本機設定的候選遠端；不得宣告遠端已收到。
- 遠端送達必須以可重驗的遠端提交包含關係或正式收據證明，不能只看本機遠端追蹤參照。

## 執行邊界

此規則預設只產生記憶體內送達計畫。沒有獨立明確授權時，不執行暫存、提交、切分支、建立分支、推送、合併、拉取、重定基底、部署或正式切換。
