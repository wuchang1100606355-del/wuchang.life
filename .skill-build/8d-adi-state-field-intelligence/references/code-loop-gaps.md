# 程式碼閉環缺口模型

## 閉環

```text
定義 → 實作 → 呼叫 → 輸入輸出 → 錯誤處理 → 測試 → 接線 → 執行證據 → 回復
```

逐環核對：

- `定義—實作`：結構、介面或規則已改，實作未同步；或實作沒有正式定義。
- `實作—呼叫`：程式存在但沒有可信呼叫者，或呼叫者仍指向舊實作。
- `輸入—輸出`：欄位、型別、版本、預設值、回傳值或序列化契約不閉合。
- `正常—錯誤`：成功路徑存在，但失敗、逾時、重試、部分完成或資源限制未處理。
- `程式—測試`：修改行為未被測試、只覆蓋舊行為，或測試與實作來自同一錯誤假設。
- `測試—接線`：單元測試通過，但正式入口、載入、路由、設定或跨節點接線未證明。
- `接線—效果`：宣稱已部署或接線，但沒有同版本執行與效果收據。
- `修改—證據`：程式已改，但結構、測試、證據、版本或權威仍指向舊座標。
- `生成來源`：修改生成產物而非來源，或生成器、模板與產物版本不一致。
- `回復閉環`：沒有前像、回復條件、相容策略或可重驗還原方法。
- `跨節點閉環`：不同節點的程式、結構、設定、權威或證據版本不一致。

## 缺口物件

```json
{
  "gap_id": "穩定識別",
  "broken_link": "斷裂環節",
  "before_coordinate": {},
  "after_coordinate": {},
  "evidence_refs": [],
  "impact_radius": "局部／群組／系統／治理／未知",
  "confidence": "已證明／強推論／弱推論／缺證據",
  "blocking": "阻斷／重大／一般／待確認",
  "unknown_frontier": [],
  "closure_conditions": [],
  "next_exact_action": ""
}
```

阻斷程度依效果決定，不依檔名或數量決定。破壞契約、形成不可逆資料效果、缺正式權威、無法安全回復或跨節點版本分裂時，至少標示重大；會使正式流程錯誤生效時標示阻斷。

找不到某環只能標示 `未知邊界`，不得宣告「沒有缺口」。
