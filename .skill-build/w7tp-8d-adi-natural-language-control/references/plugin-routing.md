# 外掛與工具融合路由

## 原則

外掛只提供「觀測能力」或「精確工具效果」，不得自動取得 Total Field（總場）、D8（第八維權威）或 Canonical（正典）地位。
同一事實由不同外掛觀測時，保留各自來源座標；不以多數決取代證據強度。

## Remote Desktop Commander（遠端桌面指揮器）

適用：
- 節點在線／離線與代理狀態。
- 遠端程序、服務、檔案與終端觀測。
- 已授權的可逆服務重啟、檔案修改與節點操作。

必要：
- 指定 device_id（裝置識別碼）。
- 操作前後重新觀測。
- 不把外掛自身 offline（離線）等同節點離線。

## GitHub（程式碼協作平台）

適用：
- repository／branch／commit（儲存庫／分支／提交）遠端證據。
- PR（合併請求）、review（審查）、CI（持續整合）與 workflow（工作流程）。
- 精確版本送達與遠端包含查證。

GitHub 狀態是 D4 Evidence（第四維證據）；不得單獨建立 D8 或 Canonical。

## Google Drive（雲端硬碟）

適用：
- 8D ADI 索引、規格、lineage（譜系）、文件與收據。
- 歷史版本與結構化文件證據。

文件內容若較現場 runtime（執行環境）舊，標為 `PROVEN_HISTORICAL（已證明歷史）` 或 stale（過期），不可覆蓋 live observation（現場觀測）。

## Plugin Management（外掛管理）

只有在現有工具無法取得必要外部系統狀態時才搜尋新外掛。
新增外掛前先回答：
- 它補哪個明確能力缺口？
- 會取得哪些資料／效果權？
- 能否只讀？
- 是否可由既有工具完成？

## 工具選擇

優先順序不是固定品牌，而是：
`最直接現場證據 → 最小副作用 → 可重觀測 → 可回復 → 最低權限`

如果兩個工具能完成同一任務，選擇能提供更精確座標與更小副作用者。
